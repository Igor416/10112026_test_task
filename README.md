# Цифровая визитка

Публичная визитка одним GraphQL-запросом: имя, ссылки, навыки, места работы с достижениями и проекты. Схема описана классами NestJS, данные лежат в PostgreSQL, доступ к ним идёт через Prisma.

Содержимое карточки задаёт `prisma/data.ts`. `prisma/seed.ts` при каждом запуске удаляет профили и создаёт визитку заново, поэтому повторный старт не оставляет дублей. Перед сдачей замените факты в `prisma/data.ts` на свои.

## Запуск

Нужны Docker и Docker Compose.

```bash
docker compose up --build
```

Контейнер API при старте применяет миграции, записывает визитку и слушает порт 3000. CLI Prisma остаётся в образе ради этих двух команд.

- Проверка живости: [http://localhost:3000/health](http://localhost:3000/health)
- Apollo Sandbox: [http://localhost:3000/graphql](http://localhost:3000/graphql)

```graphql
query {
  profile {
    name
    description
    links {
      type
      label
      url
    }
    skills {
      name
      category
    }
    experiences {
      company
      position
      period
      achievements {
        text
      }
    }
    projects {
      name
      url
      description
    }
  }
}
```

Тот же запрос лежит в `queries/profile.graphql`.

Для разработки поднимается только база, а Nest запускается на хосте. Порт 3000 при этом должен быть свободен, поэтому сервис `api` не стартуйте.

Скопируйте `.env.example` в `.env`.

| Переменная           | Зачем                                                                        |
| -------------------- | ---------------------------------------------------------------------------- |
| `DATABASE_URL`       | Адрес Postgres. На хосте это `localhost`, в compose — имя сервиса `postgres` |
| `PROFILE_SLUG`       | Ключ единственной визитки. Сейчас `main`                                     |
| `PORT`               | Порт API, по умолчанию `3000`                                                |
| `PRISMA_LOG_QUERIES` | Печатает SQL в лог, если значение `true`                                     |

```bash
docker compose up postgres -d
npm install
npx prisma migrate dev
npx prisma db seed
npm run start:dev
```

## Данные

Корень — `Profile`. От него расходятся ссылки, навыки, места работы и проекты. Достижение принадлежит месту работы: без компании ему не к чему крепиться. `slug` нужен сиду, чтобы узнавать запись после перезапуска, и в схему не входит. Порядок детей задаёт `sortOrder`.

`period` в таблице нет. Резолвер собирает строку из `startDate` и `endDate`, для текущей работы конец читается как «по настоящее время».

## Запрос

`profile` читает одну строку профиля. Ссылки, навыки, опыт и проекты закрывают отдельные `@ResolveField`: метод вызывается, только если поле есть в документе. Запрос одного имени не открывает остальные таблицы.

Достижений несколько на одну визитку. Их резолвер берёт DataLoader из контекста текущего HTTP-запроса и собирает id мест работы в один `WHERE experienceId IN (...)`. Следующий запрос получает новый лоадер.

Полная карточка стоит шесть `SELECT`: профиль, четыре прямые связи и один батч достижений. У каждой связи свой модуль с резолвером, сервисом и репозиторием. Классы схемы лежат в `src/graphql/types`: поле `projects` описывает тип `Profile`, и модуль проекта за профилем не тянется.

```text
src/
├── config/        переменные окружения
├── health/        GET /health
├── prisma/        клиент базы
├── graphql/       Apollo, enum и объектные типы
├── profile/       запрос profile
├── link/
├── skill/
├── experience/    список мест работы и строка period
├── achievement/   батч достижений на запрос
└── project/
```
